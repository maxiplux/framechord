  1. 01 / 06

    What FrameChord isQué es FrameChord

    FrameChord turns a written brief into finished media. It is one command-line tool for images, infographics, narration, podcasts, music and sound effects. It runs on your machine, keeps every input in plain YAML and Markdown files, and calls only the AI provider you choose. This narration was made with it, too.

    FrameChord convierte un brief escrito en contenido multimedia terminado. Es una sola herramienta de línea de comandos para imágenes, infografías, narración, podcasts, música y efectos de sonido. Funciona en tu equipo, guarda cada entrada en archivos YAML y Markdown, y solo llama al proveedor de IA que elijas. Esta narración también se hizo con ella.

  2. 02 / 06

    One pattern for every mediumUn patrón para todos los medios

    Every medium follows the same pattern. Write a brief. Validate it offline. Preview the exact request with a dry run, so nothing is billed yet. Generate only when the inputs are right. Then review the saved file before you use it.

    Todos los medios siguen el mismo patrón. Escribe un brief. Valídalo sin conexión. Revisa la solicitud exacta con una ejecución de prueba, así todavía no se cobra nada. Genera solo cuando las entradas sean correctas. Después, revisa el archivo guardado antes de usarlo.

  3. 03 / 06

    Define a character onceDefine un personaje una vez

    Characters are optional, but when you need one, you define it once. A character keeps its look and its voice in separate profiles, and its accepted references are reused in every new scene. Candidates never become canonical until a person accepts them.

    Los personajes son opcionales, pero cuando necesitas uno, lo defines una sola vez. Un personaje guarda su apariencia y su voz en perfiles separados, y sus referencias aceptadas se reutilizan en cada escena nueva. Las candidatas nunca se vuelven canónicas hasta que una persona las acepta.

  4. 04 / 06

    Run together, recover safelyEjecuta en paralelo y recupera con seguridad

    Independent jobs run together, within the limits you set. Each job keeps its own record, so one failure never erases another success. Identical requests reuse verified local results. And if a paid request ends in an uncertain state, FrameChord checks before paying for it twice.

    Los trabajos independientes se ejecutan juntos, dentro de los límites que tú defines. Cada trabajo guarda su propio registro, así que un fallo nunca borra otro resultado exitoso. Las solicitudes idénticas reutilizan resultados locales verificados. Y si una solicitud pagada termina en un estado incierto, FrameChord la verifica antes de pagarla dos veces.

  5. 05 / 06

    Pay per assetPaga por recurso

    There is no subscription and no FrameChord account. You pay each provider its API list price for what you generate. At October 2026 list prices, a month of forty illustrations, thirty minutes of narration, four music beds and twenty short sound effects comes to about two dollars and twenty cents.

    No hay suscripción ni cuenta de FrameChord. Pagas a cada proveedor su precio de lista de la API por lo que generas. Con los precios de octubre de 2026, un mes con cuarenta ilustraciones, treinta minutos de narración, cuatro fondos musicales y veinte efectos de sonido cortos cuesta unos dos dólares con veinte centavos.

  6. 06 / 06

    Use it from any agentÚsalo desde cualquier agente

    FrameChord works with any agent that can run a process, including Claude Code and Codex. One command installs a project skill, so your agent can write the files, validate them and call the binary. The agent plans the work. FrameChord makes the media and keeps the receipts.

    FrameChord funciona con cualquier agente que pueda ejecutar un proceso, incluidos Claude Code y Codex. Un comando instala una skill en el proyecto, para que tu agente escriba los archivos, los valide y llame al binario. El agente planifica el trabajo. FrameChord crea el contenido y guarda los recibos.

ALREADY INSTALLED? DELEGATE IT

Hand it to your agent

You do not need to learn every flag. Claude Code, Codex, Cursor, Gemini CLI, OpenCode, GitHub Copilot or any agent that can run commands can drive FrameChord for you. Say what you want in plain words; the agent writes the brief files, previews the request for free and asks before anything is billed.

  1. Install the skill in your project

    Run this once at the root of the repository where the media should live. It adds the FrameChord skill to .claude/skills/ and .agents/skills/, which every agent above discovers. Put your provider key in .env yourself; never paste keys into a chat.

    Terminal
    cd my-project
framechord init

  2. Open your agent there and check readiness

    Start a new agent session in the same folder so it picks up the skill, then send this first prompt. It is free: nothing is generated.

    First prompt
    Use the framechord skill. Check this project's FrameChord setup: run framechord config status and framechord doctor, tell me which providers and media types are ready, and what I still need to configure. Do not generate anything.

  3. Ask for media in plain words

    Name your source files, where the results should go and anything that must stay exact. The agent follows the same loop every time:

    • Author. It writes a YAML job and a Markdown brief under framechord/jobs/, files you can read, edit and commit.
    • Check. It runs framechord validate and a --dry-run, which make no provider calls, and shows you the provider, model, settings and output paths it would use. A dry run does not price the request; ask the agent to compare it with the rates in Pay per asset, and run framechord usage afterwards for labelled list-price estimates.
    • Generate. Only after you say go. This is the step your provider bills.
    • Report. It reviews the result and gives you the file paths and any job that failed or needs a decision.
Stay in charge. The skill tells your agent to keep scripts, lyrics and figures exact, preview new inputs with a dry run, generate only when you asked for it, never retry an uncertain paid request without your say-so, and leave character references for you to choose. Provider, model and voice come from your saved configuration unless you ask for a change. Saying “preview first” and “generate only when I say go” makes your expectations explicit; set request limits for large batches.

How chapters are found

  • Each # heading at or above split.heading_level starts a chapter. Headings inside code fences, #tags and indented or escaped # are ignored.
  • YAML front matter between --- lines is never read aloud. Text before the first heading becomes a preamble chapter unless you skip it.
  • Heading lines are spoken only with announce_titles: true. Chapter IDs come from the titles, for example chapter-one-the-platform.
  • validate prints every chapter with its source lines, length, request count and first and last words, and warns about links, tables or markup a voice might read out.

What you get

  • outputs/audiobook/lamp-counter/chapter-01-chapter-one-the-platform.mp3 and one file per chapter (WAV or MP3).
  • With output_mode: full: lamp-counter.mp3 with ID3 chapter markers, lamp-counter.chapters.json with start times, durations and hashes, and a lamp-counter.cue sheet.
  • With output_mode: chapters: chapter files and the chapter index only.
